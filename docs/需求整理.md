# Cage 需求整理（依据 docs/design.md，Rust 实现）

> 一句话：Cage 是面向游戏研发的配置编译与验证框架——把异构配置源（Excel/CSV/JSON/YAML/…）转换为经过验证、确定性构建的运行时配置资产。
> 技术栈：**Rust**（Cargo workspace；设计稿中的 C++ 目录结构按 Rust 惯例映射为多 crate）。

## 核心链路

Authoring Sources → Source Adapters → Canonical Model → Validation Pipeline（L0-L7）→ Normalize/IR → Target Generators → Manifest/Hash

## MVP（第一期，见设计稿 §36）

### Source Adapter（只读取解析，不做业务校验）
- [ ] Excel（workbook/sheet/header/cell/row/列/合并单元格/公式缓存值/注释）
- [ ] CSV（表头行、类型猜测交 Schema 校准）
- [ ] JSON / YAML
- 统一产出 Canonical Model：Null/Bool/Int/UInt/Float/String/Bytes/Array/Object + Source Location + 元数据

### Schema（与 Source 解耦，独立 DSL 文件）
- 字段类型（含 uint32/int64/float/string/bool/enum/array/object）、required、default、min/max、min_length/max_length、unique、enum、primary_key、reference

### Validation Pipeline（核心，逐级执行）
- L0 Parse（语法错误 E0001 族）/ L1 Schema（缺字段 E1001、未知字段 E1002）/ L2 Type（E1101）/ L3 Value（E1201 范围/正则/枚举）/ L4 Table（E1301 主键/组合唯一）/ L5 Reference（E1401 存在性、E1410 语义谓词）
- L6 Semantic（表达式规则：min_level <= max_level 这类 assert）/ L7 Game Rule（插件 Validator——MVP 只留 trait 接口）
- `cage check --level N` 可分级执行

### Diagnostics（一等公民）
- Code/Severity/Source/Location/Table/Row/Column/Field/Value/Message/Hint 全字段；错误精确定位到 文件/Sheet/单元格（如 monster.xlsx Sheet Monster Cell G27）；支持 ERROR/WARNING/INFO

### Normalize
- "100"/100/100.0 → UInt(100)、yes/true/1 → Bool(true)；相同语义 → 相同 Canonical Representation

### Target Generator（MVP 两个）
- JSON（稳定键序）、CSV
- 第二阶段：C#/Python/Lua/Protobuf/MessagePack

### Build（确定性是硬要求）
- 相同 Source+Schema+Version+Profile → 相同 Artifact+Hash+Manifest（禁时间戳/随机 ID/不稳定排序/Map 乱序）
- Build Manifest：project/profile/cage_version/schema_hash/source_hash/content_hash/artifacts 哈希表

### CLI（clap）
- `cage check`（只验证）/ `cage build`（验证+生成）/ `cage inspect`（看 Schema 与结构）/ `cage diff`（两版构建对比）
- `--profile client|server`（Profile 配置 targets 与字段可见性 targets 过滤）

### Profile 与 Field Visibility
- profile 配置文件定义 targets；字段级 `targets: [server]` 控制可见性（避免客户端/服务端两套配置）

## 第二阶段（见 §37）
C#/Python/Lua/Protobuf/MsgPack 生成器、Plugin SDK、Game Rule Validator 实装、Dependency Graph（引用图→构建顺序/增量/变更影响/循环检测）、增量构建、CI 集成（warnings_as_errors）

## 第三阶段（见 §38）
Web UI、Schema Editor、Registry（远程配置仓库）、Remote Source（Google Sheets/DB/API）、迁移、Artifact 分发

## 红线（设计稿 §39-40）
- 不做 Excel 编辑器、游戏运行时数据库、Secret Manager、游戏逻辑框架；不绑定 Unity/Unreal/Godot/Cocos
- Source Adapter 不做业务校验；Transform 不重复验证；Validator 插件不可信代码不默认执行（CI 沙箱后期考虑）

## Rust 落地口径
- Cargo workspace：`cage-core`（value/document/schema/diagnostics/validation/reference/normalize/manifest）、`cage-source-{excel,csv,json,yaml}`、`cage-target-{json,csv}`、`cage-cli`
- 错误码表进 `cage-core`（E0001/E1001/E1101/E1201/E1301/E1401/E1410 …每码一 doc）
- 确定性：BTreeMap/稳定排序、输出字节级可复现（golden 测试）
- 测试门禁：全测试绿才 commit/push（禁 force push、禁版本 tag/release）
