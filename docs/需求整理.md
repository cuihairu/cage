# Cage 需求整理（依据 docs/design.md，Rust 实现）

> 一句话：Cage 是面向游戏研发的配置编译与验证框架——把异构配置源（Excel/CSV/JSON/YAML/…）转换为经过验证、确定性构建的运行时配置资产。
> 技术栈：**Rust**（Cargo workspace；设计稿中的 C++ 目录结构按 Rust 惯例映射为多 crate）。

状态以 2026-10 的代码为准：MVP 全部交付，第二阶段除 Protobuf / MsgPack 外交付，第三阶段交付 Web UI / Schema Editor / Registry（R1–R4）；Remote Source S 系列（S1 HTTP API 源 / S2 MySQL / PostgreSQL 源 / S3 Google Sheets 源 / S4 离线语义 / S5 错误码收口 / S6 文档收口）全数交付，Template Target G 系列（Tera 引擎、官方七语言模板改写、用户自定义模板、过滤器库）已全量交付（design §22）；Artifact 分发 A 系列（bundle 导出导入 + http(s) 直推，design §47）与迁移 M 系列（声明式数据迁移，design §46）全数交付。

## 核心链路

Authoring Sources → Source Adapters → Canonical Model → Validation Pipeline（L0-L7）→ Normalize/IR → Target Generators → Manifest/Hash

## MVP（第一期，见设计稿 §36）——已全部交付

### Source Adapter（只读取解析，不做业务校验）
- [x] Excel（workbook/sheet/header/cell/row/列/合并单元格/公式缓存值/注释）
- [x] CSV（表头行、类型猜测交 Schema 校准）
- [x] JSON / YAML
- 统一产出 Canonical Model：Null/Bool/Int/UInt/Float/String/Bytes/Array/Object + Source Location + 元数据

### Schema（与 Source 解耦，独立 DSL 文件）
- [x] 字段类型（含 uint32/int64/float/string/bool/enum/array/object/map）、required、default、min/max、min_length/max_length、unique、enum、primary_key、reference

### Validation Pipeline（核心，逐级执行）
- [x] L0 Parse（语法错误 E0001 族）/ L1 Schema（缺字段 E1001、未知字段 E1002）/ L2 Type（E1101）/ L3 Value（E1201 范围/正则/枚举）/ L4 Table（E1301 主键/组合唯一）/ L5 Reference（E1401 存在性、E1410 语义谓词）
- [x] L6 Semantic（表达式规则：min_level <= max_level 这类 assert）/ L7 Game Rule（插件 Validator trait，内建样例规则 power_curve 报 E1601）
- [x] `cage check --level N` 可分级执行

### Diagnostics（一等公民）
- [x] Code/Severity/Source/Location/Table/Row/Column/Field/Value/Message/Hint 全字段；错误精确定位到 文件/Sheet/单元格（如 monster.xlsx Sheet Monster Cell G27）；支持 ERROR/WARNING/INFO

### Normalize
- [x] "100"/100/100.0 → UInt(100)、yes/true/1 → Bool(true)；相同语义 → 相同 Canonical Representation

### Target Generator
- [x] JSON（稳定键序）、CSV
- 第二阶段语言绑定见下节；Protobuf / MessagePack 未实装（规划）

### Build（确定性是硬要求）
- [x] 相同 Source+Schema+Version+Profile → 相同 Artifact+Hash+Manifest（禁时间戳/随机 ID/不稳定排序/Map 乱序；golden 测试锁定字节一致）
- [x] Build Manifest：project/profile/cage_version/generator_version/build_id/schema_hash/source_hash/content_hash/dependencies/table_hashes/artifacts

### CLI（clap）
- [x] `cage check`（只验证）/ `cage build`（验证+生成）/ `cage inspect`（看 Schema 与结构）/ `cage diff`（两版构建对比）
- [x] `--profile client|server`（Profile 配置 targets 与字段可见性 targets 过滤）

### Profile 与 Field Visibility
- [x] profile 配置文件定义 targets；字段级 `targets: [server]` 控制可见性（避免客户端/服务端两套配置）；结构不可缺字段被 profile 隐藏报 E9006

## 红线（设计稿 §39-40）
- 不做 Excel 编辑器、游戏运行时数据库、Secret Manager、游戏逻辑框架；不绑定 Unity/Unreal/Godot/Cocos
- Source Adapter 不做业务校验；Transform 不重复验证；Validator 插件不可信代码不默认执行（CI 沙箱后期考虑）

## Rust 落地口径
- Cargo workspace：`cage-core`（value/document/schema/diagnostics/validation/reference/normalize/manifest/snapshot/edit/registry/remote）、`cage-source-{excel,csv,json,yaml,http,db,sheets}`、`cage-target-{json,csv,cs,py,lua,ts,cpp,go,java,template}`、`cage-cli`
- 错误码表进 `cage-core`（E0001/E1001/E1101/E1201/E1301/E1401/E1410 …每码一 doc；预留码在 [validation.md](validation.md) 标注）
- 确定性：BTreeMap/稳定排序、输出字节级可复现（golden 测试）
- 测试门禁：全测试绿才 commit/push（禁 force push、禁版本 tag/release）
